## Flush+Reload 攻撃について

今回では Meltdown において実際に値を獲得するために使う。

Flush+Reloadは、CPUキャッシュへのアクセス時間の違いを利用するサイドチャネル攻撃手法である。
手法は以下のとおりである。

1. 観測対象となるメモリ領域をキャッシュから追い出す（Flush）。
2. 秘密の値に応じたアドレスにアクセスさせることで、対応するキャッシュラインをキャッシュに載せる。
3. 各候補のメモリを再度読み込み（Reload）、アクセス時間を測定する。

アクセスした箇所がキャッシュヒットしやすくなるため、キャッシュヒットしたアドレスから秘密の値を推測できる。

## Meltdown について

### 概要

Meltdown を使うと、メモリ内の値をアドレスから本来アクセスが禁止されていても拾ってくることができる。

### 関連する話

- 仮想アドレス空間
- アウトオブオーダー実行

### 内容

#### 手法

例として、以下のような疑似コードを考えてみる。
観測用の配列はあらかじめ用意され、対応するキャッシュラインはFlushされているものとする。

```c
#define PAGE_SIZE 4096
#define KERNEL_ADDRESS 0xFFFF000000001000UL // 仮のアドレス

unsigned char *secret = (unsigned char *)KERNEL_ADDRESS;
unsigned char probe[256 * PAGE_SIZE];

unsigned char value = *secret;
unsigned char hoge = probe[value * PAGE_SIZE];
```

ここで、`KERNEL_ADDRESS` は読み取りたいカーネルメモリのアドレス、`secret` はそのアドレスを指すポインタである。`value` が読み取りたい秘密の値に当たる。

また、`256` は `unsigned char` が取り得る256通りの値に対応するため、`PAGE_SIZE` は候補同士のアクセス先を十分に離し、キャッシュ上で区別できるようにするためにある。

従来の Linux では、ユーザープロセスのページテーブルにもカーネルメモリがマッピングされていた。
ただし、ユーザーモードからのアクセスは許可されず、カーネルモードのアクセスのみ許可とされていた。

CPU では、高速化のためにアウトオブオーダー実行を用いており、命令の実行と、その結果を確定する処理を分離している。
アウトオブオーダー実行では、命令間の依存関係を考慮しながら、プログラムに書かれた順番とは異なる順序で命令を実行する。
一方、命令の結果を正式に確定させる処理は原則としてプログラムの順番どおりに行われるため、実行されたものの結果が確定していない命令が存在する。

Meltdown に脆弱な CPU では、カーネルメモリへのアクセスが権限違反になるにも関わらず、読み込んだ値が後続の命令にも一時的に渡ってしまう場合がある。

そのため、CPUは一時的に `probe[value * PAGE_SIZE]` にアクセスできてしまい、対応するメモリ領域のデータがCPUキャッシュに読み込まれることがある。
権限違反によってページフォールトが発生した場合後続の命令の実行結果は破棄されるが、副作用であるキャッシュへの追加は取り消されない。

そこで、Flush+Reload を使用して `probe` の各候補の読み込み時間を測定することで、値を推測することができる。

#### 対策

Meltdown は、アクセス権限のないメモリの値が CPU 内部で一時的に利用可能であり、副作用から情報が漏れることが問題であった。

そのため、権限チェックをするだけでなく、ユーザーモードの際にはカーネルメモリの大部分を仮想アドレス空間にマッピングしないようにすることで、アクセスできないようにした。

これを Kernel Page Table Isolation (KPTI) と言う。

KPTI では、ユーザーモード用とカーネルモード用のページテーブルを分離する。
システムコールや割り込みによってカーネルへ移行する際にはカーネル用ページテーブルに切り替え、ユーザーモードに戻る際にはユーザー用ページテーブルに戻す。
これにより、ユーザーモードではカーネルメモリの大部分がマッピングされなくなり、Meltdown による情報漏えいを防ぐ。
